# 술기 및 처치 문서 작성 가이드

## 범위와 정본 위치

실제 시행·확인·관리 방법은 `source_notes/07 Skills`에 둔다. 수술 전후 관리, 수액·영양, 수술 체위와 해부, 장루 수술의 원칙, 예방항생제처럼 분과 이론에 해당하는 내용은 해당 분과에 둔다. 술기 섹션을 임상총론으로 확장하지 않는다.

기존 문서의 파일 위치, `id`, 이름, 상세 URL, 영상과 출처는 보존한다. 저장·열람 기록은 `skill:<id>`를 계속 사용한다. 분류는 폴더 이름이 아니라 Markdown frontmatter를 기준으로 생성한다. 기존 문서의 이동·병합이나 ID 변경은 별도 검토가 필요하다.

## 분류 메타데이터

```yaml
---
id: "stable-document-id"
name: "문서 이름"
category_id: "monitoring"
category_name: "환자 모니터링"
category_order: 8
subcategory: "기본 진찰"
subcategory_order: 2
icon_name: "ActivitySquare"
order: 1
video_url:
sources:
- "기관: 직접 관련 문서·연도 | https://direct-source-url"
---
```

같은 `category_id`의 `category_name`, `category_order`, `icon_name`은 같아야 한다. 문서는 `subcategory_order`, `order`, 제목 순서로 배치된다. 해당 분류에 이미 있는 원문 메타데이터를 확인한 뒤 추가한다.

| category_id | 분류 | 순서 |
| --- | --- | ---: |
| cpr | 소생술 | 1 |
| airway | 기도·호흡처치 | 2 |
| blood | 채혈·혈관접근 | 3 |
| tubes | 관·배액관리 | 4 |
| advanced | 천자·검체채취 | 5 |
| wound | 창상·국소처치 | 6 |
| injection | 투여·진정 | 7 |
| monitoring | 환자 모니터링 | 8 |
| ward | 환자안전·의료절차 | 9 |

기존 혈관 라인 분류 URL `/skills/category/line`은 `blood`의 `legacy_category_ids: ["line"]`로 유지한다. 별칭은 다른 분류와 중복 지정하지 않는다. 분류 ID는 표시 이름이 바뀌어도 가능한 한 유지한다.

## 본문 구성

본문의 큰 목차는 다음 다섯 가지를 같은 순서로 사용한다. 세부 목차는 주제에 맞게 선택하고, 정해진 항목 개수나 문장 수를 강제하지 않는다.

1. 개요·원리
2. 적응증·금기증
3. 시행
4. 결과
5. 합병증·사후 관리

```markdown
# 문서 이름

## 개요·원리
적용 범위와 필요한 해부·생리 또는 작동 원리.

## 적응증·금기증
시행 조건, 피해야 할 상황과 대안.

## 시행
### 사전 확인과 준비
환자 평가, 처방·부위·위험 확인과 필수 준비물.

### 핵심 과정
방법·장치 선택과 필요한 알고리즘.

## 결과
성공 확인, 측정·검체·판독의 의미와 한계.

## 합병증·사후 관리
이상 징후와 대처, 감시, 유지·제거와 추적 기준.
```

`##` 제목마다 절이 생성되며 원문 순서대로 표시된다. `###`·`####` 하위 제목, 목록, 강조, 표를 사용할 수 있다. 결과에 들어갈 내용이 부족하면 검토 대상으로 남기고 임의의 정상값이나 성공 기준을 만들지 않는다.

참고 자료는 별도 큰 목차로 만들지 않는다. Frontmatter의 `sources`에 기관·문서명·지침 연도와 URL을 저장하며, 웹에서는 문서 끝에 작은 글씨의 출처 링크로 표시한다. 영상이 있는 문서는 접힌 교육 영상 영역을 사용한다.

기존 `Indications / Supplies / Precautions / Complications / Steps` 형식은 호환 입력으로 계속 지원한다. 현재 원문은 다섯 목차로 재배치하고, 세부 절차와 `Warning:` 내용은 보존한다. 개요는 본문의 첫 절에서 한 번만 표시하며, 오디오 복습도 동일한 본문 절을 사용한다.

표는 헤더 다음 줄에 `| --- | --- |` 구분선을 넣고 표 행을 연속해서 작성한다.

## 임상 내용 작성 원칙

- 직접 관련된 공식 지침이나 신뢰할 수 있는 임상 참고자료를 확인하고 출처와 적용 연도를 남긴다.
- 환자군, 시행 환경과 권고의 적용 범위를 명시한다.
- 실제 행동을 바꾸는 수치, 금기, 실패 대처와 도움 요청 기준을 설명한다.
- 병원마다 다른 처방·희석·장비·보고 체계는 기관 프로토콜 확인 항목으로 구분한다.
- 고급 술기는 무감독 시행을 전제하지 않고 준비·보조·확인·감시 범위를 명시한다.
- 질환 이론을 이름만 비슷한 술기 문서에 몰아넣지 않는다. 수혈 제제 선택은 혈액 이론, 제제 확인·투여·감시는 술기다.

## 문제은행 연결

관련 문서 유형 `skill`은 `/skills/<id>`, `lab`은 `/lab-img/<slug>`로 연결한다. 질병·CC·약물 연결은 기존 방식을 유지한다. 연결 검색 카탈로그는 원문 데이터 동기화 단계에서 생성한다.

술기·검사 문서를 연결해도 이론문제가 자동 생성되지는 않는다. 해당 유형과 ID를 명시적으로 연결한 이론문제만 관련 문제로 집계한다. 문항이 없으면 0개로 표시하며 다른 CC 문제로 대체하지 않는다.

서버 저장 검증과 웹 클라이언트를 함께 반영해야 새 `skill / lab` 링크를 온라인 편집 화면에서 저장할 수 있다.

## 최소 확인

술기만 수정했을 때는 다음 동기화로 범위를 제한할 수 있다.

```powershell
Set-Location apps/medicine-web
node scripts/sync-generated-data.mjs --skills-only
node --test scripts/test-skills-manifest.mjs
```

전체 배포 데이터는 GitHub Actions의 기존 동기화 과정에서 생성한다. 전체 로컬 프로덕션 빌드를 반복하지 않는다. UI·연결 로직 변경 시 관련 파일의 린트·타입과 필요한 단위 테스트를 확인한다. 검증용 산출물은 사용자 허락 없이 삭제하지 않는다.
